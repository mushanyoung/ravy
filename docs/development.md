# 开发与文档维护

每次从根目录 AGENTS.md 开始，只读取目标目录的规则与当前需要的文档。
先确认现有行为、用户改动和验证入口；新功能先提供最小可运行骨架及质量检查。

把工作拆成小而完整的逻辑单元。每个单元实现、补充核心规则/边界/异常测试、
更新说明并运行适用检查，通过后立即 `git add <本单元文件>` 和 `git commit`。
提交信息说明目的，不把无关清理混入功能。不要自动 push 或部署。

常规选择自行判断。只有缺失信息实质改变目标或范围时提问，并继续其他工作。
实现期间正常调试和修复；不安排独立代码审查、reviewer agent 或 AI 审查工作流。

现行架构、操作、测试策略和决策理由放 `docs/`；历史证据放 `docs/archive/`，
不让历史执行状态冒充当前验证结果。模块规则放对应目录的 AGENTS.md。
文档只记录项目约束、理由和操作，避免复述可从代码看出的细节。
代码行为、命令或架构发生变化时，在同一提交更新文档和链接并删除过时内容。

交付简要列出实现、Git commits、实际检查和结果、未解阻塞。
本地验证与 GitHub Actions 的实际状态分开报告；未执行的检查明确写“未执行”。
